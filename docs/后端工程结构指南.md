# 后端工程结构指南

> 项目：完整电商系统 + 秒杀模块
> 本文档规定后端代码的分层架构、包结构、统一返回与异常处理规范。

---

## 一、分层架构（四层）

```
前端
  │ HTTP 请求
  ▼
┌─────────────────────────────┐
│ Controller 控制层（接客）      │  接收请求、参数校验、调用 Service、返回结果
├─────────────────────────────┤
│ Service 业务层（大脑）         │  业务规则：下单、算钱、扣库存、判断权限
├─────────────────────────────┤
│ Mapper 数据访问层（搬运工）     │  执行 SQL：增删改查，忠实搬运不做业务判断
├─────────────────────────────┤
│ Entity 实体层（快递箱）         │  对应数据库表，字段和表一一对应
└─────────────────────────────┘
  │
  ▼
MySQL
```

### 职责边界（重点）
- **Controller 不写业务**：只接客、校验参数、转交 Service、包装返回。
- **Service 不写 SQL**：只写业务规则，通过 Mapper 拿数据、判断、组合。
- **Mapper 不做判断**：只执行 SQL，把结果返回给 Service，由 Service 判断。
- **Entity 不写逻辑**：纯数据容器，对应数据库表。

> 经典例子：检查"用户名是否被占用"——Mapper 执行 `SELECT ... WHERE username=?`（查），Service 判断"查到了就报错"（判）。

## 二、包结构（目录规范）

```
com.example.mall
├── MallApplication.java        # 启动类
├── controller/                 # 控制层：AuthController、ProductController、CartController、OrderController
├── service/                    # 业务层接口：AuthService、ProductService...
├── service/impl/               # 业务层实现：AuthServiceImpl...
├── mapper/                     # 数据访问层：UserMapper、ProductMapper...（MyBatis-Plus 接口）
├── entity/                     # 实体层：User、Product、Sku、Order、OrderItem...
├── dto/                        # 数据传输对象：接收前端参数（RegisterDTO、LoginDTO）
├── vo/                         # 视图对象：返回给前端的数据（LoginVO、ProductVO）
├── common/                     # 通用：Result 统一返回、异常处理、常量、工具类
└── config/                     # 配置类：MyBatisPlusConfig、WebConfig、SecurityConfig
```

### dto 和 vo 为什么要单独建？
- **dto（接收前端传参）**：前端传来的参数可能和数据库字段不完全一致，用 dto 接收、校验，不直接暴露 Entity。
- **vo（返回前端数据）**：返回的数据可能是多张表拼出来的（如商品详情 = 商品 + SKU 列表），用 vo 组装，不直接把 Entity 全量返回（避免把 password 等敏感字段返回）。
- **原则**：Entity 不直接进 Controller 层，进出的都是 dto/vo。

## 三、统一返回结构 Result

所有接口返回统一格式（对应接口设计文档）：

```java
public class Result<T> {
    private Integer code;      // 200成功 / 400参数错 / 401未登录 / 403无权限 / 500服务器错
    private String message;    // 提示信息
    private T data;            // 具体数据
}
```

提供静态方法：`Result.success(data)`、`Result.error(code, message)`。

---

## 四、统一异常处理

后端不能把 Java 异常直接甩给前端。用全局异常处理器兜底：

```java
@RestControllerAdvice
public class GlobalExceptionHandler {
    // 业务异常 → 返回 400 + 提示信息
    // 未登录异常 → 返回 401
    // 兜底异常 → 返回 500 + "系统繁忙"
}
```

- 业务上要"主动报错"的地方，抛自定义业务异常（如 `BusinessException("库存不足")`）。
- 统一异常处理器捕获后转成 Result 格式返回，前端统一解析。

## 六、技术栈落地对照

| 技术 | 在骨架里的位置 |
|------|---------------|
| Spring Boot | 启动类 + 依赖 |
| MyBatis-Plus | mapper 层（继承 BaseMapper 即得增删改查） |
| MySQL | 数据源配置 |
| JWT | 登录后签发 token（认证模块） |
| Redis / RabbitMQ | 第二阶段加入（秒杀） |
