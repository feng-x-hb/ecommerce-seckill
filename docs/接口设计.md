# 接口设计文档

> 项目：完整电商系统 + 秒杀模块
> 阶段：第一阶段（电商主流程）
> 本文档定义前后端通信的 API 协议：路径、方法、参数、返回值。

---

## 一、统一返回格式（所有接口遵守）

后端所有接口都返回同一结构，前端统一解析：

```json
{
  "code": 200,
  "message": "成功",
  "data": {}
}
```

| 字段 | 说明 |
|------|------|
| code | 业务状态码：200 成功 / 400 参数错误 / 401 未登录 / 403 无权限 / 500 服务器错误 |
| message | 给用户看的提示信息 |
| data | 具体数据（对象或数组） |

> 为什么不用 0/1？因为只有"成功/失败"两种状态不够用，需要区分"未登录、没权限、参数错"等不同情况，前端才能分别处理（如跳登录页）。

## 二、认证模块（/api/auth）

### 1. 注册
- **方法/路径**：POST /api/auth/register
- **是否登录**：否（公开）
- **请求参数**：
  | 参数 | 类型 | 必填 | 说明 |
  |------|------|------|------|
  | username | string | 是 | 用户名，唯一 |
  | password | string | 是 | 密码（明文传，后端加密存储） |
  | phone | string | 是 | 手机号，唯一 |
- **返回 data**：注册成功的用户 id
- **说明**：id 由数据库自增生成，前端不传；密码后端用 BCrypt 加密后存库，绝不存明文。

### 2. 登录
- **方法/路径**：POST /api/auth/login
- **是否登录**：否（公开）
- **请求参数**：
  | 参数 | 类型 | 必填 | 说明 |
  |------|------|------|------|
  | account | string | 是 | 用户名或手机号（二选一） |
  | password | string | 是 | 密码 |
- **返回 data**：
  ```json
  {
    "token": "eyJhbGciOiJIUzI1NiIs...",
    "userInfo": { "id": 1, "username": "x", "role": 0 }
  }
  ```
- **说明**：token 是 JWT 令牌，前端保存，后续请求放请求头 `Authorization: Bearer <token>`，后端凭它识别用户身份。

### 3. 获取当前登录用户信息
- **方法/路径**：GET /api/auth/me
- **是否登录**：是
- **返回 data**：userInfo（id、username、nickname、avatar、role）
- **说明**：前端刷新页面后，用这个接口恢复登录状态（拿 token 换用户信息）。

## 三、商品模块（/api/product）

### 1. 商品列表（分页）
- **方法/路径**：GET /api/product/list
- **是否登录**：否（公开）
- **请求参数**：
  | 参数 | 类型 | 必填 | 说明 |
  |------|------|------|------|
  | page | int | 否 | 页码，默认 1 |
  | size | int | 否 | 每页条数，默认 10 |
  | categoryId | long | 否 | 按分类筛选 |
  | keyword | string | 否 | 搜索关键词 |
- **返回 data**：
  ```json
  {
    "total": 100,
    "list": [
      { "id": 1, "title": "iPhone 15", "mainImage": "...", "price": 5999.00 }
    ]
  }
  ```
- **说明**：total 是总条数，前端用它算总页数；分页避免一次返回大量数据拖慢页面。

### 2. 商品详情
- **方法/路径**：GET /api/product/{id}
- **是否登录**：否（公开）
- **返回 data**：商品完整信息 + 该商品的所有 SKU 列表（规格、价格、库存）

### 3. 分类列表
- **方法/路径**：GET /api/category/list
- **是否登录**：否
- **返回 data**：分类树（parent_id 组装成树形）

## 四、购物车模块（/api/cart）

> 全部需要登录，前端带 token。

| 接口 | 方法/路径 | 参数 | 返回 |
|------|-----------|------|------|
| 加购物车 | POST /api/cart | skuId, quantity | 成功/失败 |
| 购物车列表 | GET /api/cart/list | 无 | SKU 信息 + 数量 + 勾选状态 |
| 改数量 | PUT /api/cart/{id} | quantity | 成功/失败 |
| 删除 | DELETE /api/cart/{id} | 无 | 成功/失败 |
| 勾选/取消 | PUT /api/cart/{id}/checked | checked(0/1) | 成功/失败 |

- **加购逻辑**：同一用户 + 同一 SKU 已存在则数量累加（靠数据库联合唯一索引兜底）。

## 五、订单模块（/api/order）

> 全部需要登录。

### 1. 创建订单（下单）
- **方法/路径**：POST /api/order/create
- **请求参数**：
  | 参数 | 类型 | 必填 | 说明 |
  |------|------|------|------|
  | skuItems | array | 是 | [{skuId, quantity}]，从购物车勾选的项 |
  | receiverName | string | 是 | 收货人 |
  | receiverPhone | string | 是 | 收货电话 |
  | receiverAddress | string | 是 | 收货地址 |
- **返回 data**：orderNo（订单号）
- **说明**：下单时后端做三件事：① 校验库存 ② 扣减库存（数据库层防超卖）③ 生成订单 + 明细（含价格快照）。

### 2. 模拟支付
- **方法/路径**：POST /api/order/{orderNo}/pay
- **是否登录**：是
- **返回 data**：支付结果
- **说明**：本地模拟，直接标记支付成功（真实项目对接微信/支付宝回调）。

### 3. 取消订单
- **方法/路径**：POST /api/order/{orderNo}/cancel
- **说明**：仅"待支付"状态可取消；取消后恢复库存。

### 4. 订单列表
- **方法/路径**：GET /api/order/list
- **参数**：page, size, status（可选筛选）
- **返回 data**：订单列表（含状态、金额、下单时间）

### 5. 订单详情
- **方法/路径**：GET /api/order/{orderNo}
- **返回 data**：订单信息 + 明细列表（快照的商品名/图/单价）
