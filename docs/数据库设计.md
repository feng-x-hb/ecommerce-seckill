# 数据库设计文档

> 项目：完整电商系统 + 秒杀模块
> 阶段：第一阶段（电商主流程）
> 本文档记录数据库表结构设计，先设计后建表。

---

## 一、总体设计思路（先读这一节）

### 1. 角色模型：1 张 user 表 + role 字段
- 买家 / 商家 / 管理员 共用一张 `user` 表（账号身份），用 `role` 字段区分。
- 原因：登录时只查一张表，一套密码校验逻辑通吃所有角色，符合 RBAC 思路。
- 角色约定：`0 = 买家`，`1 = 商家`，`2 = 管理员`。

### 2. 专属信息用 1 对 1 扩展表
- 商家专属字段（店铺名、营业执照等）不放 user 表，放独立的 `merchant_profile` 表。
- 普通用户在 merchant_profile 里没有对应行，天然表示"不是商家"。
- 避免宽表大量空值、职责混乱、扩展难的问题。

## 二、user 用户表（已定稿）

| 字段名 | 类型 | 约束/说明 | 备注 |
|--------|------|-----------|------|
| id | BIGINT | 主键，自增 | 系统内部唯一标识，关联订单/购物车用 |
| username | VARCHAR(50) | 唯一索引 | 登录名（用户自己设定） |
| password | VARCHAR(60) | 非空 | BCrypt 加密后固定 60 字符，绝不存明文 |
| phone | VARCHAR(11) | 唯一索引 | 手机号，登录/注册用；本地不做短信验证但字段保留 |
| nickname | VARCHAR(50) | 可空 | 用户自己 DIY 的展示名 |
| avatar | VARCHAR(255) | 可空 | 头像图片 URL 路径，不存图片二进制 |
| role | TINYINT | 非空 | 0买家 / 1商家 / 2管理员 |
| status | TINYINT | 非空，默认0 | 0正常 / 1禁用（平台封禁用） |
| created_at | DATETIME | 非空 | 创建时间，MyBatis-Plus 自动填充 |
| updated_at | DATETIME | 非空 | 更新时间，MyBatis-Plus 自动填充 |

### 字段设计要点
- **password 为什么是 VARCHAR(60)**：BCrypt 加密结果固定 60 字符，所以长度不多不少。
- **phone 为什么用 VARCHAR 不用 INT**：手机号是"标识符"不做运算，INT 最大 21 亿装不下 11 位手机号。
- **avatar 为什么用 VARCHAR**：只存图片路径，图片文件放磁盘，数据库存"在哪"。
- **唯一索引**：username、phone 保证账号唯一，同时登录查询走索引不扫全表。

## 四、category 分类表（已定稿）

| 字段名 | 类型 | 约束/说明 | 备注 |
|--------|------|-----------|------|
| id | BIGINT | 主键，自增 | 分类唯一标识 |
| parent_id | BIGINT | 非空，默认0 | 上级分类 id；0=顶级分类（自关联树形结构） |
| name | VARCHAR(50) | 非空 | 分类名称 |
| sort | INT | 默认0 | 排序号，越小越靠前 |
| status | TINYINT | 默认0 | 0显示 / 1隐藏 |
| created_at | DATETIME | 非空 | 自动填充 |
| updated_at | DATETIME | 非空 | 自动填充 |

### 设计要点
- **parent_id 自关联**实现无限层级分类（顶级 parent_id=0，子级指向父级 id）。
- 例：手机数码(0) → 手机(指向手机数码) → 智能手机(指向手机)。

## 五、product 商品表（已定稿）

| 字段名 | 类型 | 约束/说明 | 备注 |
|--------|------|-----------|------|
| id | BIGINT | 主键，自增 | 商品唯一标识 |
| seller_id | BIGINT | 非空，索引 | 商家 id，关联 user.id（role=1） |
| category_id | BIGINT | 非空，索引 | 分类 id，关联 category.id |
| title | VARCHAR(100) | 非空 | 商品标题 |
| subtitle | VARCHAR(200) | 可空 | 副标题/卖点 |
| main_image | VARCHAR(255) | 可空 | 主图 URL |
| images | TEXT | 可空 | 图片列表（JSON 数组） |
| detail | TEXT | 可空 | 商品详情（富文本/HTML） |
| price | DECIMAL(10,2) | 非空 | 列表展示价=当前最低 SKU 价（冗余，需同步） |
| status | TINYINT | 默认1 | 0下架 / 1上架 |
| sales | INT | 默认0 | 销量（冗余统计） |
| created_at | DATETIME | 非空 | 自动填充 |
| updated_at | DATETIME | 非空 | 自动填充 |

### 设计要点
- **price 是冗余字段**：存"最低 SKU 价"供列表页快速展示；商家改 SKU 价格时后端需同步更新（方案 A：冗余+同步）。
- **真实售价在 sku.price**，下单结算以 SKU 价为准；实付价（减优惠券）在结算页计算，不入商品表。

## 六、sku 商品规格表（已定稿）

| 字段名 | 类型 | 约束/说明 | 备注 |
|--------|------|-----------|------|
| id | BIGINT | 主键，自增 | SKU 唯一标识 |
| product_id | BIGINT | 非空，索引 | 关联 product.id（1 对 N） |
| specs | VARCHAR(255) | 非空 | 规格描述，JSON 格式如 {"颜色":"黑","容量":"256G"} |
| price | DECIMAL(10,2) | 非空 | 该规格真实售价 |
| stock | INT | 非空，默认0 | 库存（第一阶段直接放这里，秒杀阶段再升级） |
| status | TINYINT | 默认1 | 0停用 / 1启用 |
| created_at | DATETIME | 非空 | 自动填充 |
| updated_at | DATETIME | 非空 | 自动填充 |

### 设计要点
- **product 存公共信息、sku 存规格独有信息**（1 对 N），避免公共字段重复存储。
- **库存第一阶段放 sku.stock**，用 `UPDATE ... WHERE stock>0` 做数据库层防超卖；秒杀进阶阶段再引入 Redis 预扣 + MQ 异步。

## 七、cart_item 购物车表（已定稿）

| 字段名 | 类型 | 约束/说明 | 备注 |
|--------|------|-----------|------|
| id | BIGINT | 主键，自增 | 购物车项唯一标识 |
| user_id | BIGINT | 非空，索引 | 哪个用户的购物车 |
| sku_id | BIGINT | 非空，索引 | 哪个商品配置（SKU） |
| quantity | INT | 非空，默认1 | 数量 |
| checked | TINYINT | 默认1 | 是否勾选：1勾选/0取消，结算只算勾选的 |
| created_at | DATETIME | 非空 | 自动填充 |
| updated_at | DATETIME | 非空 | 自动填充 |

### 设计要点
- **联合唯一索引 (user_id, sku_id)**：保证"同一用户 + 同一 SKU"只有一行；重复加入时程序做数量累加。不同 SKU 组合允许产生多行。
- **checked 勾选字段**：支持"只结算勾选的商品"，体验对齐主流电商。

## 八、order 订单表（已定稿）

| 字段名 | 类型 | 约束/说明 | 备注 |
|--------|------|-----------|------|
| id | BIGINT | 主键，自增 | 订单内部标识 |
| order_no | VARCHAR(32) | 唯一索引 | 订单号（时间+随机数），用户/对账可见，不用自增id |
| user_id | BIGINT | 非空，索引 | 下单用户 |
| status | TINYINT | 非空 | 状态机：0待支付/1已支付/2已发货/3已完成/4已取消/5已关闭 |
| total_amount | DECIMAL(10,2) | 非空 | 商品总价 |
| discount_amount | DECIMAL(10,2) | 默认0 | 优惠金额（优惠券） |
| pay_amount | DECIMAL(10,2) | 非空 | 实付金额 = 总价 - 优惠（下单时算好存起来） |
| receiver_name | VARCHAR(50) | 非空 | 收货人（快照） |
| receiver_phone | VARCHAR(11) | 非空 | 收货电话（快照） |
| receiver_address | VARCHAR(255) | 非空 | 收货地址（快照） |
| pay_time | DATETIME | 可空 | 支付时间 |
| created_at | DATETIME | 非空 | 自动填充 |
| updated_at | DATETIME | 非空 | 自动填充 |

### 设计要点
- **订单号独立**：随机生成（时间+随机数），不暴露业务量、不可猜测。
- **金额三字段**：total/discount/pay，下单时算好存库；`pay = total - discount` 可做金额校验。
- **收货信息快照**：用户改地址不影响历史订单。
- **状态机**：6 个状态控制业务流转，防止非法操作（如未支付就发货）。

## 九、order_item 订单明细表（已定稿）

| 字段名 | 类型 | 约束/说明 | 备注 |
|--------|------|-----------|------|
| id | BIGINT | 主键，自增 | 明细唯一标识 |
| order_id | BIGINT | 非空，索引 | 所属订单（1 对 N） |
| sku_id | BIGINT | 非空 | 买的哪个 SKU |
| product_name | VARCHAR(100) | 非空 | 商品名（快照） |
| product_image | VARCHAR(255) | 可空 | 商品图（快照） |
| spec_desc | VARCHAR(255) | 可空 | 规格描述（快照，如"黑/256G"） |
| price | DECIMAL(10,2) | 非空 | 成交单价（快照） |
| quantity | INT | 非空 | 数量 |
| sub_total | DECIMAL(10,2) | 非空 | 小计 = 单价 × 数量 |

### 设计要点
- **快照机制**：商品名/图/规格/单价在下单时原样复制，商品表后续改动不影响历史订单。
- **order_id 关联 order 表**：一个订单多行明细（1 对 N）。
